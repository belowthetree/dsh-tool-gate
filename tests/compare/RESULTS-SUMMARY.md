## 怎么读

1. **完成度没有退化**：28 次运行（20 + 8 次重复）全部 ✅，门控从没把任务卡死。
2. **工具面是确定性收益**：根代理首请求 23 个 / 17,796 B → 6 个 / 4,991 B（3.6× / 3.6×），
   与模型行为无关。
3. **token 方向性更省、但单次运行不可作结论**：`gated` 与 `gated-root` 在这批运行里行为上
   几乎等价（所有委派都走了 `delegate`，而 `delegate` 预留的子代理在两种配置下都被门控），
   它们之间的差异就是噪声——同一任务同一轮里最大到 **2.4×**（arch-split rep1：738k vs 313k）。
   同机制两臂能差 2.4×，单次 A/B 的结论不可信。
4. **按任务看方向**：5 个任务 × 3 次重复里，gated 家族在 7/8 个格子 ≤ control，
   唯一持平的是 toolkit-notes rep1；arch-split rep1 的内部排序被噪声打乱。
5. **复杂任务上"只门控根代理"最稳**（gated-root 两次都低、三次均值最低），但如上，
   这与 gated 机制等价，更多说明这次运行里子代理路径恰好更短，不能当成机制结论。
6. **`delegate-only` 不是银弹**：强制精确子代理清单在第 1 次全量里最省（0.79×），
   但两次复杂任务重复里只排中游（0.46× / 0.46×，绝对值 656k vs gated-root 424k）。

## 下一步（要真结论必须做）

- 每格至少 3–5 次重复，报告均值 + 极差；现在只有 arch-split 够 3 次。
- 需要"只门控根代理且委派走 `subagent`"的对照臂，否则 `gated` 与 `gated-root` 分不开。
- 固定模型温度/采样（若路由支持），或把每格跑成配对样本（同轮次交替）。
- 单次运行成本：简单任务 40–120 s，复杂任务 100–360 s；每格 3 次 × 5 任务 × 4 臂 ≈ 30–60 分钟。

读法与观察：

- 每个任务、每个臂都是 ✅；门控家族在**每一个任务**上都低于 control（0.16×–0.69×），不再像旧设计那样被单任务噪声吃掉。
- 差距不是只靠缓存：`delegate-only` 的未命中输入是 control 的 0.55×，说明**首次处理量本身**也降了（旧设计里这一项基本持平）。
- 子代理 token 从 control 的 1.24M 降到 0.30M–0.59M，是总量差的第二大来源。
- 行为观察（`RESULTS-catalog.md` 的门控表）：`select_tools` 通常 1 次；`arch-split`/gated 里模型重复 select 了 5 次同一组工具（可优化：提示"一次即可，重复调用不会更快"）；`delegate` 的工具清单偶尔先猜 `bash`/`pwsh`（本组合没有），被拒后重试。
- 仍然每格只跑 1 次；上一轮测得"机制等价两臂单轮可差 2.4×"的噪声仍在，所以**比值**可看，绝对值和臂间小差距不可当结论。

## 两次重复的合并读法（当前设计）

| 臂 | rep1（catalog） | rep2（catalog2） | 均值 | 比值 rep1 | 比值 rep2 | 均值比值 |
| --- | --- | --- | --- | --- | --- | --- |
| control | 1,849,044 | 1,347,699 | 1,598,372 | 1.00 | 1.00 | 1.00 |
| gated | 770,363 | 859,103 | 814,733 | 0.42 | 0.64 | **0.51** |
| gated-root | 830,354 | 796,238 | 813,296 | 0.45 | 0.59 | **0.51** |
| delegate-only | 617,339 | 510,512 | 563,926 | 0.33 | 0.38 | **0.35** |

- **方向稳定**：两轮 × 5 任务 = 40 个门控格子，全部完成，且每个格子的合计 token 都低于同轮 control（0.30×–0.86×）。
- **噪声假设被证实**：`gated` 与 `gated-root` 在这批运行里机制等价（委派都走 `delegate`，预留子代理两边都被门控），单轮相差 8%，但**均值只差 0.18%**（814,733 vs 813,296）。所以臂间小差距不可读，均值可读。
- **delegate-only 稳定最省**：两轮都是第一（0.33× / 0.38×），未命中输入也是唯一明显低于 control 的（0.55× / 0.61×）。
- 单轮绝对值仍会漂：control 1.35M–1.85M，所以**只看比值，不看绝对值**。

## 会话记录在哪

每次运行的目录：`.compare-run/runs/<label>/<arm>-<task>/`

| 文件 | 内容 |
| --- | --- |
| `transcript.md` | 可读的完整对话：user / runtime-context（含本轮工具目录原文）/ assistant / tool call（含参数）/ tool result / developer 增量；根与子代理各一节 |
| `transcript.jsonl` | 同样内容，一行一条 JSON |
| `run.log` | 这次运行的 stdout/stderr |
| `project/` | 被改动的 fixture 副本（复杂任务就是评这里） |
| `.dsh/` | 隔离的 DSH_HOME |
| `.sessions/…/session.v4.jsonl.zstd` | DSH 持久会话日志（zstd JSONL，真正的 session record） |

查看：`node sessions.mjs list` / `node sessions.mjs show <label> <arm> <task>` / `open` 打印目录。
默认保留历史运行（按 label 分目录），只有 `--fresh` 才清空 scratch root。
